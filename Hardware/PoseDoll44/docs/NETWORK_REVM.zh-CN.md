# 全身网络接口（Rev M 数字原型候选）

本文件对应 [network_revM.json](../mechanical_manifest/network_revM.json)。六个节点固件已编译；四种 PCB 的布线、壳体安装和两款线束表已交付。ERC、DRC 及原理图/PCB 一致性检查均为零违规，尚无实物通信验证。H1 单轴固件及已测试的 UE/模拟器没有改动，也没有连接串口或发送模拟的硬件数据。

## 通道分区

| 节点 | 负责部位 | 测量数 | 协议索引 |
|---|---|---:|---|
| N1，兼 USB 网关 | 腰部 | 3 | 3–5 |
| N2 | 胸、颈头 | 6 | 6–11 |
| N3 | 左肩带至左手腕 | 9 | 12–20 |
| N4 | 右肩带至右手腕 | 9 | 28–36 |
| N5 | 左髋至前脚掌 | 7 | 21–27 |
| N6 | 右髋至前脚掌 | 7 | 37–43 |

索引 0–2 是骨盆固定参考，不占传感器接口。新 N1 的腰部接 P1–P3，不能照旧 44 颗传感器的分配接 P4–P6。每个区域最多九口，P1–P9 的 CS GPIO 依次为 2、4、5、6、7、8、9、10、14。SCK/MOSI/MISO 为 12/11/13；CAN TX/RX 为 17/18；USB 19/20 保留。

控制器候选为 ESP32-S3-WROOM-1-N8，区域板直接安装模块。当前板形为 40 × 86 mm、四层、1.2 mm 厚；该布局是制造候选，需厂家确认叠层与工艺后进行首件验证。SPI 初始 250 kHz、mode 1；逐口独立缓冲 SCK/MOSI/MISO、CS 独立控制，目标是减少长线分支互相影响。每口源端阻尼候选 100 Ω，现有传感器 MISO 源端 33 Ω。阻值和最长线束必须通过波形/丢帧实测后定型，降频不能代替信号完整性设计。[模块资料](https://www.espressif.com/sites/default/files/documentation/esp32-s3-wroom-1_wroom-1u_datasheet_en.pdf)、[缓冲器资料](https://www.ti.com/lit/ds/symlink/sn74lvc125a.pdf)。

## 电源和 CAN 候选

使用 5 V 外部电源、各区独立 3.3 V 降压，不增加电池。适配器采用稳压 5 V / 3 A 候选，并要求短路保护。线束压降和电流计算见 `verification/revM_harness_power_<角色>.json`；MCU 电流、转换效率和接触电阻是待测假设，不能把计算通过当作供电实测。每块区域板都必须由外部 5 V 供电，USB VBUS 不连接节点电源。USB 仅传数据；由 [TS3USB221E](https://www.ti.com/lit/ds/symlink/ts3usb221e.pdf) 隔离数据线，只有检测到主机 VBUS 时才使能，芯片断电时采用其 Ioff 隔离功能。降压采用 [TPS62162](https://www.ti.com/lit/ds/symlink/tps62162.pdf)，固定 3.3 V 版本的 FB 引脚接地。LM66100 不在当前电路中。区域原理图共 142 个器件、123 个网络，原生 KiCad ERC 为 0 违规；完整 PCB 和电源回路的候选文件在 `generated/revM/electronics`；零违规不代表温升、EMC 或实际供电已合格。

CAN 收发器选择 3.3 V 的 TCAN332DR 候选，避免对远端 5 V 电压同时提出收发器的稳压要求。芯片支持断电时总线高阻；实际板上的保护器件、接地和线束仍需一起验证。[TCAN33x 官方资料](https://www.ti.com/lit/ds/symlink/tcan332.pdf)。

协议为传统 11-bit CAN，500 kbit/s，不使用 ESP32-S3 不具备的 CAN FD 控制器能力。总线按 **N6 → N1 → N5 → N3 → N2 → N4** 串联，只在 N6、N4 各装 120 Ω 端接。N1 是中间节点兼网关，不额外端接；电源独立六路星形分配。当前没有 G0 节点或固定底座。裁线及针序见 [线束说明](WIRING_REVM.zh-CN.md)。目标 60 次/秒同步采集，各节点在接收到 SYNC 后 8 ms 内完成本地采样，网关在发出 SYNC 后 14 ms 结束收集。各节点晶振未校时，不能把本地 8 ms 当作全身同时采样窗口。27 个标准 8-byte 帧按保守 135 bit/帧估算约占 43.7% 带宽；这只是初算，不含启动、诊断突发与重传，也不是已测吞吐量。

## 同一批次采集

每一批从空数据开始，不能借用上一帧的关节读数凑齐本帧。

固件的 CAN 帧分配如下，均使用 8 字节数据、小端数值：

| ID | 内容 |
|---|---|
| 0x080 | 新采集会话 epoch，uint64 |
| 0x081 | SYNC：cohort uint32、网关时间低 32 位 |
| 0x100 + 节点号 | 节点 boot_id uint64 |
| 0x120 + 节点号 | 确认 epoch uint64 |
| 0x180 + 节点号 | END：cohort uint32、开始偏移 uint16、采集跨度 uint16，单位 μs |
| 0x200 + 节点号 ×16 + 分组号 | cohort uint32、两个传感器 word uint16 |

节点收到新 epoch 后必须中止旧采集、清理发送队列，再确认会话。网关完成身份/区域核对并清理旧接收帧后才开始 SYNC。数据包只有 cohort，因此队列清理和会话确认是必需的配套规则，不能只抄数据包格式。32-bit cohort 回卷时另起 epoch。N1 的本地腰部数据也走同样的组装检查。

END 必须晚于该节点所有分组。缺组、重复组、超时、读数编码不合法或节点重启，都使该节点在当前批次保持 missing。读到传感器故障时应传 invalid，不把故障读数改成零。这里只是有线设备间的完整性协议，不提供对抗恶意设备的身份认证。

## USB 诊断帧

PD41 与原 H1 有独立 magic。COBS 分帧，末尾 0 分隔；COBS 解码后为 164 字节，末尾 CRC32 校验前 160 字节。

头部为 `<4sBBHQQQQIHH`，共 48 字节：magic `PD41`、版本 1、类型 1、正文长度 160、设备 ID、boot ID、递增序号、网关时间 μs、采集窗 μs、6-bit 节点到齐掩码、通道数 44。随后 44 个 uint16 word，再接六组（开始偏移、采集跨度）uint16。此处传输的是网关时间基准下的保守包络 `[0, END 中断接收时刻 − SYNC 发出前时刻]`，包含 CAN 仲裁和发送等待，最大 14 ms；不是节点自己的 delay/span。缺失节点的时间字段全零。END 原始 delay/span 另作合理性检查；接收时间取自 CAN 中断，任务排队延迟不会把迟到帧伪装成准时帧。

- `0x0000–0x3FFF`：有效 14-bit 原始计数，只能出现在实际测量轴。
- `0x4000`：明确的骨盆固定参考；另用于 CAN 奇数分组的末尾填充，不能填实际测量轴。
- `0x8000 | flags`：传感器无效，flags 是 H1 已定义的非零五位故障位，不包含一个可用角度。
- `0xFFFF`：当前批次缺失。
- 其他编码拒绝。

桥接器只能把完整、有效且经过实体校准的批次作为姿势发送给 UE。当前 Python 工具提供全身诊断窗口、显式选择端口后的记录，以及离线批次检查，见 [全身诊断说明](FULL_DIAGNOSTIC.zh-CN.md)；诊断窗口的 `calibrated` 始终为 false。另有显式设备绑定的离线实体校准及协议转换入口，见 [构建与校准](BUILD_AND_CALIBRATE_REVM.zh-CN.md)；没有自动替用户生成的实体零点，也没有连接当前 UE 会话。硬件零点、传感器方向、磁场验证和设备绑定不能由测试用计数代替。

离线验证覆盖 Python 桥接/协议/校准、9 个 C 核心边界场景及 C/Python 黄金字节流一致性；最终次数和结果以 `verification/revM_offline_tests.json` 为准。ESP-IDF 6.1 下 N1–N6 六个配置均成功编译，记录见 `verification/revM_firmware_build_work.json`；生成的板级引脚配置由网络清单自动核对。固件使用 ESP-IDF 新 `esp_twai` 接口，依次发送各组后才发 END，并在会话变化时清空旧队列。

没有烧录、串口连接、实物 CAN 测试或真实全身数据采集。零点、轴方向、磁场、供电波形及长线 SPI 仍须在实物阶段检验。编译和离线测试结果不替代这些验证。
