# 给本地 Codex 的执行入口

用户已经有可用的 UE 5.8.2 插件和 Python 模拟器，是硬件设计新手，拥有 Bambu Lab A1 mini。你的任务是主导完整 44 轴硬件的机械 CAD、电子设计、固件、桥接、装配说明和验证脚本；用户只负责按图采购、打印、插接、测量与反馈。不把零件选型、针脚判断、焊接芯片、总线排错交给用户自行解决。

## 开工前

阅读本目录所有设计文档及 contracts。检查当前仓库、用户未提交修改和现有测试。当前计划的仓库基线仅用于比对，禁止 reset 或覆盖用户资产。

首先完成 H0：完整 44 轴的结构布局、负载和供电预算、工具探测、实际器件候选资料与购买前检查。不是先随手画一个铰链。全身布局可以是参数化的占位外形，但必须包含所有关节轴、板子、插头、线束通道、支架和装配工具空间，并明确哪些是真实供应商尺寸、哪些仍是占位假设。

## 软件兼容底线

当前 `FProfile::Load` 固定读取虚拟 profile、模拟 calibration 和 Body35 capability。新增明确的设备配置选择及实体校准文件；不覆盖旧文件，不篡改 golden vectors，不冒用虚拟设备身份通过握手。

44 轴 ID/顺序与 contracts 一致。轴之间存在真实偏移时，由机械 CAD 导出新的实体 profile。传感器 raw -> UE 校准/FK -> Manny Control Rig 的所有权保持不变，不能在固件里直接生成 Manny 骨骼或把物理读数先校准一遍再让 UE 校准第二遍。

保持既有 Capture、Undo、重开、Clutch、掩码、断线冻结的回归测试。严格区分实测、缺失、固定、模拟；不把未装配的 43 根轴伪装为读数为零的 44 轴实物。

## 工具与工作目录

机械用 CadQuery/Python 作为可再生源；电子用可编辑的 KiCad 原生文件、受支持的编程接口和 kicad-cli 检查/导出；固件使用 ESP-IDF CLI。MCP 只是可选包装，不是实时数据链路，也不应成为交付物能否复现的依赖。

在仓库中建议新增 `Hardware/PoseDoll44/`、`Firmware/PoseDollHardware/`、`Tools/PoseDollHardwareBridge/`。不要搬动旧工程。安装前记录工具版本和现有环境；CAD/固件环境与当前 Python 3.13 模拟器环境隔离。大规模安装、采购、下单、烧录熔丝、远程打印均需用户明确授权。

## 第一轮必须交付

1. 全身参数化布局、44 轴映射清单、支架与走线路径、关键姿势碰撞报告；列出尚未解决的限制。
2. 三类关节的结构方案及最大负载预算；一套实际选型的单轴测试关节、打印公差试片与传感器定位夹具。正式输出前将实际编码器板、磁铁、轴、垫片、螺丝规格冻结。
3. 少量已焊接模块的购买清单：确切型号、数量、替代条件、接口照片/视图、总价和为什么需要。仅在用户确认后采购，不购买整套 44 路。
4. 一键构建/检查、编号 STL 与 STEP、装配分解视图、逐页接线说明、自动诊断程序、测量记录模板。买得到且需要预焊的接口必须明确写入采购条件。
5. `H0_REPORT.md` 与 `H1_RELEASE_CHECKLIST.md`：真实执行结果与 `not_run` 分开，不虚构工具截图或测试通过。

在单轴可靠后，尽早测试密集三轴组件，验证磁场串扰、轴碰撞、线束弯曲和手感。不要等完整个人偶都打印后才发现肩膀无法抬手。

## 不得用“自动检查通过”代替工程判断

CAD 实体有效不等于能承重；碰撞采样不等于穷尽全部姿势；KiCad ERC/DRC 不等于电路正确；传感器 14 位不等于人偶精度 0.022 度；打印夹具也不是可溯源的角度标准。所有性能结论必须附设备、方法、负载、环境、原始记录及误差边界。

完成本轮后，把用户要做的事情整理为“打开哪个文件、装哪个零件、点哪个按钮、看哪里、记录什么”，不能要求用户自己设计或根据感觉接线。
