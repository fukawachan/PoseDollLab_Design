# 仓库衔接、固件与通信设计

状态：硬件协议设计草案。既有 `posedoll.sensor/1` 是已有接口；下文 CAN/USB 为待实现并验证的新接口，不代表仓库当前已有这些能力。

## 1. 仓库审阅结论

检查到提交 `7c22e075fe0efe295ce2935a8bb2a92cff0b6def`。README 报告 UE 5.8.2 / CL 56702186，44 路输入、54 节点 FK、Manny 绑定、Capture 等功能已经在本地验证。用户也确认软件可用。本次没有在 UE 内重跑这些测试，仓库不含生成的验收日志与二进制资产。[R1,R2]

直接检查的关键限制：

- `Plugins/PoseDoll/Source/PoseDollCore/Private/PoseDollCore.cpp` 的 `FProfile::Load` 固定加载 `virtual_humanoid_44_v1.json`、`virtual_zero_pi_v1.json` 和 `body35_capabilities.json`，并校验 44 轴。
- `Plugins/PoseDoll/Source/PoseDollEditor/Private/PoseDollSession.cpp` 初始化依赖当前 Manny 配置。不能只把硬件 TCP 数据接进去就假设实体校准会自动生效。
- 当前 JSON sample schema 禁止额外字段；序号与时间戳是十进制字符串。不可添加任意硬件诊断字段而仍声称协议兼容。[R4,R5]

补充源码核对：当前 `ParseSample` 已接受 null 与 missing/invalid 的配对，`FDecoder` 会拒绝用它们计算姿势，因此硬件故障可使用合法的无效样本表达，不必把它们变成协议解析错误。`Handshake` 已有 `source_kind`，但当前所查看的函数只检查非空，没有把它保存进输出身份；新增硬件/混合来源的 UI 与采集限制时，必须完整保留和传播来源类型。不能仅发送这个字符串就认为既有界面已具备区分能力。[R5]

保留虚拟配置和已通过的测试。新增可明确选择的 profile/calibration/capability 组合，以允许的本地目录或注册表定位，不让网络发送任意文件路径控制加载。选择变化要冻结预览、清空连续角状态并重新握手。旧的默认模拟器流程应保持工作。

## 2. 数据所有权

```
编码器整数与诊断 → 区域节点 → CAN → 网关 → USB CDC
    → Python Hardware Bridge → 既有 TCP raw 协议
    → UE unwrap / zero / sign / ratio → 实体 FK → Manny / Control Rig
```

固件读取原始绝对编码值及健康状态。Bridge 按 `raw_rad = count * 2π / 16384` 换算为弧度，但不扣机械零位，不镜像左右，不重定向骨架。UE 仍是机械校准与姿势映射的权威实现。

如果以后引入单传感器非线性修正 LUT，必须设计清楚该变换与校准的顺序、单位、版本和哈希，并新增接口/测试；本版不悄悄在固件中加入不可追踪的“纠正”。

Bridge 复用当前模拟器的 TCP 编码与握手逻辑。H0 必须读取实际实现，确认服务端/客户端角色、端口、长度前缀字节序、消息上限和会话规则，不根据记忆另写一套相似协议。

## 3. 区域采集固件

每个节点配置稳定 node_id、hardware_id、boot_id、板卡版本、端口映射及 manifest 哈希。支持最多十路端口，实际装配数由区域角色决定。启动时关闭不需要的无线功能，检查传感器、配置和电源状态后才进入健康状态。

驱动要测试：已知读数、SPI 延迟回包、奇偶错误、错误清除、无磁铁、过强/过弱场、返回固定旧角度、MISO 被拉低、线断开、上电顺序和看门狗恢复。诊断寄存器的判据从购买的实际芯片资料核对，不能只把一个 `readAngle()` 成功当作全功能驱动。

获取每个节点本轮最早/最晚读取时间、所有端口的原始值和状态，不能一边读一边覆盖上一轮对外缓冲。整体提交，避免半新半旧。增加数据就绪/状态读取开销后，再测定最多十路的采集时间。

## 4. CAN 方案与带宽预算

基线为经典 11-bit CAN、500 kbit/s，网关广播 100 Hz epoch 同步；区域收到本轮同步后采样并在本轮截止时间内发回。同步发送顺序和数据就绪时刻不等于所有芯片内部 ADC 同时采样，必须测量实际采样窗口；目标不超过 5 ms。

建议每个传感器编码为 16-bit：低 14 位计数，高 2 位健康状态（00 valid、01 missing、10 invalid、11 reserved）。`fixed` 不由未测量硬件伪造；它只来自经过确认的机械 capability。诊断详情另发低频帧。计数无效时低 14 位规定为 0，不能靠该值判断零姿势。

一个 8-byte 数据帧携带 `epoch_u16 + 3 * axis_word_u16`。总线 ID 标识 node 和 fragment；字节序统一 little-endian。不足三个轴的最后片段按已知区域长度处理，并校验填充为零。例示 ID 规划：SYNC `0x080`、数据 `0x100 + 4*node_number + fragment`、低频诊断 `0x200 + node_number`；正式实现前锁定 CAN ICD 并测试冲突。十路最大需要四片，fragment 取 0..3。

当前分区 6/6/9/9/7/7，每轮数据片数 2+2+3+3+3+3=16，加一帧同步=17。按每个满长帧约 135 个总线位的保守估算，100 Hz 加六个节点各 10 Hz 的单帧诊断，负载约 `(17*100+6*10)*135/500000 = 47.52%`。这只是预算，不包括重试、额外诊断、启动握手和真实实现开销。完整固件应保留余量，稳态目标低于 60%，通过实际 CAN 统计确认；不合格则先减少诊断/优化协议或降低采集频率，不伪造 100 Hz 完整样本。

16-bit epoch 每 655.36 秒回绕；以 boot/session、有限接收窗口及模比较处理，不按普通整数递增比较。每个节点重启后必须重新加入健康 cohort，旧帧不能补齐新 epoch。`boot_id` 和 manifest 信息通过启动握手与低频状态传输；未完成身份确认不接受该节点数据。

10 ms 周期内初定 8 ms cohort 截止。某片缺失时在已知 44 轴槽位中标记受影响轴 missing，不能把上轮角度复用为 valid。身份变化、配置不匹配或系统级故障应结束当前有效设备会话。节点拆卸导致 CAN 干线中断时也可能影响其他区域，必须如实报告。

## 5. USB 网关与主机 Bridge

网关只有一个对外 USB 设备；六个节点不分别连接电脑。推荐原生 USB CDC，固件日志走单独调试接口，不能混入数据流。使用 ESP-IDF 对实际开发板的 USB 功能和引脚做本地验证。

USB 二进制建议使用 COBS 分帧、0 分隔符、显式版本/消息类型/长度、CRC32；上限设为 4096 bytes，未知版本拒绝。字段至少包括网关与节点会话关联、递增样本序号、网关单调时间、epoch、采样窗口、44 个 axis word、映射哈希标识。CRC 的确切算法参数、字节序和测试向量须在正式 ICD 中冻结，不只写“CRC32”四个字。

网关记录组内采集时间窗口和故障原因。主机不得用“刚收到数据的当前时间”冒充原采集时间，也不得通过源端时间戳直接减 PC 时钟来伪造端到端延迟。延迟指标必须注明时钟域；测量采集到 PC 接收需要建立时钟映射或硬件对时实验。

Bridge 扫描可识别硬件的串口/USB 标识，经用户选择连接。持久设备身份与每次启动会话分开；断线重连不自动恢复 Live。只缓存最新完整样本，有边界和超时，不用无限队列制造越用越延迟。

向 UE 发出的 sample 完全遵循已有 schema：`protocol=posedoll.sensor/1`，`raw_angles_rad` 的未知项为 null，`axis_status` 为对应枚举，`sequence` 和 `sender_monotonic_us` 为十进制字符串。哈希按实际文件字节计算，不重新格式化 JSON 后沿用旧哈希。详细硬件诊断存到独立日志或另一个版本化接口，不能越过 `additionalProperties:false`。

默认硬件输入配置只绑定本机回环地址。MCP 用于测试、采集报告或低频控制，绝不承担实时 60 Hz 数据链路。

## 6. 实体校准

校准流程不是“现在是什么姿势都一键当零位”。提供按部位组合的 N pose 定位夹具，指示插销/基准面和安装方向；轴的位置必须是机械上可重复的已知参考。

先建立安装/磁场健康状态，再读多次原始值，估计稳定零点；使用已知正向运动确定 sign；直接同轴测量默认 joint_rad_per_sensor_rad=1。使用已有 UE unwrap 逻辑验证跨 raw 0/2π 的连续性，不把每一帧重新压到 -π..π。未经唯一性验证的多圈状态不猜测。本版硬限位总行程应小于一圈并留裕量，分别核对零点到允许范围的分支。

保存设备序列号、模块版本、磁铁/传感器更换记录、44 轴零点、方向、周期、机械限位、校准时间与夹具编号。实体 profile 和 calibration 单独版本化。Bridge 与 UE 必须协商同一份有效组合。

独立量角/定位基准用于检查绝对误差；只看同一传感器自身输出、或用同一份 CAD 派生的一对夹具相互验证，只能证明部分自洽，不能证明绝对精度。若参考工具精度不足，将结果标成 repeatability_only，不声称已经达到绝对角精度指标。

## 7. 分阶段试验中的数据真实性

单关节或单臂阶段，其他尚未存在的轴不是真实硬件测量。优先在硬件诊断视图观察实测部分，再使用明确标注的 `LAB_MIXED_SOURCE` 测试模式将模拟补全输入送到 UE。

混合模式必须显示真实轴清单、模拟轴清单、实验身份和本次使用的配置，不伪造 FullBody44 设备。混合试验模式不允许进入普通生产 Capture；现有独立虚拟模拟器的正常采集功能仍然保留，不受此限制；若为验证允许写实验序列，使用隔离测试资产并显式启用，不覆盖用户正式作品。元数据留在独立日志/测试 manifest 中；若需协议新字段就正式版本化。

只有实际存在、可验证机械固定的轴才可声明 fixed。Body35 capability 不能用来掩盖整条未装配手臂。正式 44 轴验收要求 44 颗传感器真实接入，断开任意一颗不能仍显示“全部硬件健康”。

## 8. 新增软件验收

新增 profile 选择、USB Bridge、校准向导和硬件诊断面板，同时保持旧模拟器全部回归。采集到的最终结果仍应是 UE 的原生可编辑 Control Rig key；关闭硬件、Bridge、MCP 及重启 UE 后仍可播放和手动调整。

需要记录从物理模块到数字轴到目标姿势的完整证据链。出现错误时先显示是哪颗传感器/哪个区域无效，再决定是否冻结，不把所有故障归为“网络连接失败”。
